### 坑：`adb reverse` 规则在本机活不过一次调用

```
调用 1：adb reverse tcp:8080 tcp:8080   → --list 显示 UsbFfs tcp:8080 tcp:8080
调用 2：adb reverse --list             → 空
```

每次调用 adb 都打 `daemon not running; starting now`，daemon 随 Bash 调用结束被杀
（同 MEMORY.md 里「adb server 活不过一次 Bash 调用」），规则跟着 daemon 一起没。
→ **真机联调不要把 reverse 写进沙箱脚本**，要让用户在自己的 Android Studio Terminal
或系统 Git Bash 里执行，那里的 daemon 是长活的。

1. 酷我 `jsToJson` 原本用正则给裸 key 补引号，会把 `MINFO:'level:p,bitrate:320,...'` 字符串**内部**的

2. `MusicSourceService.play` 的缓存 key 不区分 fallback，失败结果缓存 30 秒，
   导致「先试播失败 → 再点自动换源」直接命中旧失败结果，换源形同虚设。已在读缓存侧加判断
3. `HttpJson.fetch` 强制覆盖 UA，改成 headers 里给了 User-Agent 就不覆盖

## 推荐页首屏入场动画（接上一轮）

需求：打开应用直接进推荐页，入场动画与旧首页一致 —— 飞入 + 自上而下渐显同时进行。

- `RecommendFragment` 用 `springEnter`（位移 + 透明度同帧，解析弹簧）按 top→bottom 错峰：
  标题 20 / 副标题 70 / 每日卡 120 / 分区标题 180 / 行 220+40n / 音源歌单 400 / 本机歌单 500 / footer 560
- 只在 `entrancePlayed=false` 时播一次；行挂在 `submitList` 提交回调上补播（网络数据晚到）
- **关键坑：动画必须锚在第一帧**。`ValueAnimator.start()` 就定 startTime，
  而模拟器从 onCreate 到首帧要 6–10 秒，提前 start 的动画首帧直接跳终态，看起来像没播。
  改法：启动动画和页面入场都包在 `doOnPreDraw { }` 里
- `MainActivity.entranceDelayMs()` 让内容在启动层开始淡出（progress≈82%）那一刻入场，
  与 logo 动画重叠 200ms，不出现「看完 logo 再重播」
- 空态文案不参与位移，延后 640ms 淡入，避免和飞上来的分区标题叠影
