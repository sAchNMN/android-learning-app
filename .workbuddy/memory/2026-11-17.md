## 关键决策（后续不要推翻，要改先看文档理由）

1. **页面层级判定**：一级 = 底部 Tab；二级 = 列表/聚合；三级 = 详情/表单/一次完整业务动作。
   结算原来是店铺详情里的弹窗，P2 拆成独立 `CheckoutActivity`。
2. **购物车不落库**，只存 DataStore；服务端只在 preview/create 时按提交内容重算。
3. **金额一律服务端算**，create 的请求体不含任何金额字段。
4. **状态变更用带 `WHERE status=原状态` 的 UPDATE（CAS）**，禁止 select 判断再 update。
5. **下单幂等**用 `clientToken` + Redis SETNX（5 分钟），失败要显式 delete 占位。
6. **待支付超时用惰性取消**，不写定时任务：在查详情/查列表时判断 `create_time + 15min`。
7. **订单时间轴读 order 表的时间戳字段**，不读 `takeout_order_status_log`（那是审计流水，会重复）。
8. **店铺评分重算不累加**：`rating = AVG(review.rating)`。
9. **P2 不拆 feature 模块**，UI 全在 `app/ui/{shop,order,address,...}` 分包，因为结算域要读店铺域的购物车。
10. `takeout_shop.category` 文本保留不动，新增 `category_id`；筛选走 id，展示走文本。

## 踩到的坑

1. **`android/local.properties` 缺失导致命令行编译失败**（`SDK location not found`）。
   已创建，`sdk.dir=C\:\\Users\\34759\\AppData\\Local\\Android\\Sdk`，该文件被 .gitignore。
2. **`colorPrimary` 不在 material 的 R 里**，是 appcompat 的属性：
   `MaterialColors.getColor(view, androidx.appcompat.R.attr.colorPrimary)`。
3. **Activity 属性初始化早于 attach**，属性初始化里读 `intent` 会拿到 null。
   Adapter 依赖 intent 时必须 `by lazy`，在 onCreate 首次访问才构造。
4. `android:paddingVertical` 是 API 26 属性，minSdk 24 上无效，用 paddingTop/Bottom。
5. data class 里 `@StringRes` 写在构造参数上会报 "annotation applied to value parameter only"，
   写 `@param:StringRes` 消警告。

## 又踩的坑

6. **Chip 动态创建拿不到 Filter 样式**：`Chip(context)` 用主题默认 chipStyle（Assist），
   选中态没视觉反馈。正确做法是 inflate 一个带 `style="@style/Widget.Material3.Chip.Filter"`
   的布局（`chip_category.xml`）。
7. **ChipGroup 程序设置 isChecked 会触发 listener**，导致重建分类栏时多发一次请求。
   重建前 `setOnCheckedStateChangeListener(null)`，重建完再挂回去。
8. 排序 Chip 要**先 `check()` 再挂 listener**，否则初始化就触发一次 selectSort。
