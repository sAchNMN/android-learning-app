## 登录"网络连接失败"排查结论

**账号密码**：`admin` / `（若依默认口令）`（若依超管，`docs/api.md` 已记录）。curl 直连 `POST /login` 返回 200 + token，凭据没问题。

**两个独立坑，都踩了：**

1. **装的是旧 APK**。`./gradlew assembleDebug` 只编译不安装，模拟器上还跑着之前用
   `-PapiBaseUrl=http://127.0.0.1:8080/` 打的包。必须 `adb install -r` 才生效。
   → 验证手段：看界面底部"接口地址"，或读 `app/build/generated/source/buildConfig/debug/.../BuildConfig.java` 里的 `BASE_URL`。

2. **`10.0.2.2:8080` 从 App 里连不上**（OkHttp `SocketTimeoutException: failed to connect ... after 15000ms`），
   但宿主机 `curl 127.0.0.1:8080` 正常、后端确实在 `0.0.0.0:8080` LISTENING。
   注意设备 shell 里 `toybox nc -w 3 10.0.2.2 8080` 报 PORT_OK **是假阳性**，别拿它当结论。
   怀疑 Windows 防火墙拦入站（未取证，未动防火墙）。

**可用方案（已验证）**：`adb reverse tcp:8080 tcp:8080` + 用 `127.0.0.1` 打包。
- 这条规则能跨 Bash 调用存活（adb server 是常驻 daemon），但 adb server 重启/模拟器重启后要重来。
- 完整流程必须一条命令跑完：install → reverse → am start → 输入 → 截图。

```
./gradlew assembleDebug -PapiBaseUrl=http://127.0.0.1:8080/
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb reverse tcp:8080 tcp:8080
```

**结果**：登录 → 200 → GET /getInfo 带 Bearer token → 进入"点外卖"首页，3 家店正常加载。

## 项目转向：外卖 → 音乐播放器（feat/music-glass 分支）

**分支收拢**：`--no-merged` 剩两个分支，实为已被 master 吸收的平行实现（server 侧几乎逐字节相同，
android 侧被底部导航重构取代），用 `git merge -s ours` 收进图里，不做三方合并。

**整体换血**（`a5cf47c` 起）：
- 删掉 app 模块全部外卖 UI（约 50 个 kt + 40 个 layout + androidTest）
- 新增 `music/data`（MediaStore 本地库、RecentlyPlayed）、`music/player`（media3 服务 + 控制器）、
  `music/ui`（首页/搜索/云端/资料库/正在播放 + 玻璃控件）
- `core:common` 放统一曲目模型 `MusicTrack`，`core:network` 放 `MusicApi`/`MusicRepository`
- 后端新增 `server/business/music` 模块 + `sql/05_music_schema.sql`，`verify-compile.sh` 通过

**三个踩坑（都花过时间）**：

1. **NestedScrollView 里放 wrap_content 的 RecyclerView 会量成 0 高度**，列表直接消失。
   → 改成「单 RecyclerView + 多类型条目（sealed HomeItem）」，横滑作为一个条目内嵌横向 RV 且给固定高度。

2. **`content://media/external/audio/albumart/{albumId}` 在 Android 10+ 是空的**，MediaProvider 不再维护该表。
   嵌入式封面必须 `ContentResolver.loadThumbnail(音频uri)`。→ 自定义 Coil `Fetcher.Factory<Uri>`
   拦 `/audio/media/` 路径，App 实现 `ImageLoaderFactory` 注册。

3. **Coil 2 的 `Options.size` 不能直接当 Int 比较**（编译报 compareTo 候选不匹配），
   改用固定 512px 缩放尺寸，别绕 API。

**并发写入**：本次会话期间有另一个进程反复把 `res/values/*.xml` 还原成旧版（主题一度丢失，
亮色下 `Theme.Aurora` 不存在导致启动崩溃）。对策：写完立刻 `git commit`，之后 checkout 也只是回到自己版本。

**测试素材**：ffmpeg 造 8 条带 ID3 的 mp3 推到 `/sdcard/Music` + MEDIA_SCANNER_SCAN_FILE 广播即可被索引。
`gradients` 滤镜的 x0/y0/x1/y1 是归一化坐标，给像素值会得到一片淡色（踩过）。最终选不带内嵌封面，
让 App 的 `CoverArt` 兜底生成渐变封面。

## 云端曲库实跑（下午，补上"代码通了但没实跑"的环）

整条 App → 后端 → mp3 流式播放链路已跑通。卡住的四点全在环境，不在业务逻辑：

1. **`ruoyi.profile` 指向 `D:/ruoyi/uploadPath`，而 D: 是可移动盘**。盘一抽走，
   `/profile/**` 直接 `No static resource`（HTTP 500）。改成 `C:/ruoyi/uploadPath`。
2. **Redis 便携版配了三条 save 规则**，bgsave 失败后进入 `MISCONF … stop-writes-on-bgsave-error`，
   若依启动时写字典缓存直接失败、整个上下文起不来。已改成 `save ""` + `stop-writes-on-bgsave-error no`。
3. **旧 jar 被运行中的 java 占着**，`mvn package` 会在 repackage 阶段报
   "Unable to rename ruoyi-admin.jar → .original"。打包前先杀 java 进程。
4. **`MusicRepository` 把 `/profile/music/01.mp3` 原样交给 ExoPlayer**，被当成本地文件路径，
   报 `FileNotFoundException`。必须 `absolute()` 补 baseUrl —— 这条是实跑才暴露的，
   单测和编译都发现不了。

**放行**：控制器类上 `@Anonymous`，若依 `PermitAllUrlProperties` 启动时自动收集，
不用改被 gitignore 的 `SecurityConfig`（重 clone 也不会丢）。

**素材**：从 `C:\Users\34759\Music` 抽 10 首 FLAC 转 192k mp3 → `C:/ruoyi/uploadPath/music/01..10.mp3`，
库里的 `title/artist/duration_ms` 与之对齐见 `sql/05_music_schema.sql`。

**验证结果**：`/app/music/tracks` 返回 10 条带 `url`；`/profile/music/01.mp3` 200 + `audio/mpeg`，
带 Range 返回 206；App 云端页显示 10 首，点播 `state=PLAYING` 且 position 正常推进。
